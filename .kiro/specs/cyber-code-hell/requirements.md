# 赛博阎王殿 · 需求规格（P0 Demo）

> 项目代号：Cyber Code Hell  
> 范围：可现场演示的 JS/TS 单文件离线审查闭环。  
> 重要声明：规则检测是启发式辅助，命中只称“疑似问题”，不宣称绝对安全；禁止执行用户提交的陌生代码。

## 1. 目标与非目标

### 目标

- 让用户在 3 分钟内体验“押送 → 三司会审 → 阎王判决 → 修复还阳 → 真实验证”的完整故事。
- 所有判决来自真实规则扫描；所有验证结果来自真实静态检查。
- 无网络、无 AI Key 时可完整演示。

### 非目标（P0 不做）

- 不支持 JS/TS 以外的语言，不做多文件仓库、依赖漏洞、类型检查或运行时测试。
- 不执行用户代码，不自动提交 PR，不接入数据库/Docker/微服务。
- 不做真实 AI 审查（列为 P1）、GitHub 导入与分享卡片（P2）。

## 2. 用户与旅程

目标用户：参加黑客松的开发者、评委、对代码质量有兴趣的工程师。

主旅程：打开鬼门关 → 选择内置卷宗或编辑代码 → 押送审判 → 查看三司罪状与行号证据 → 申请还阳 → 查看 Diff → 确认采用 → 语法与规则复扫 → 看到“本次修复验证通过” → 可撤销补丁。

## 3. EARS 需求与验收标准

### R1 代码输入

当用户进入鬼门关时，系统应提供可编辑的 JS/TS 单文件输入、文件名、语言切换和字符计数。  
**Given** 用户输入合法代码，**When** 点击押送审判，**Then** 使用该源码执行真实扫描。  
**Given** 空输入或超过 50,000 字符，**When** 点击押送，**Then** 阻止提交并显示明确错误，不生成判决。

### R2 语言限制

系统只应接受 JavaScript / TypeScript 单文件，并对其他语言显示“暂不支持”。  
**Given** 当前 UI 仅暴露 JS/TS，**When** 用户查看语言限制，**Then** 明确显示 MVP 范围，不虚假声称支持其他语言。

### R3 规则扫描与证据

当执行审判时，系统应对源码运行确定性启发式规则，并为每条命中输出 ruleId、判官、严重度、置信度、从 1 开始的行号、真实证据行、解释与建议。  
**Given** 源码包含 `eval`、硬编码凭据、SQL 拼接、空 catch、嵌套循环或调试输出，**When** 扫描，**Then** 返回对应 Issue，证据必须来自源码对应行。  
**Given** 注释中的 `eval` 或普通字符串内容，**When** 扫描，**Then** 不误报。

### R4 三司会审

系统应按领域将 Issue 分派给黑无常（安全）、白无常（性能）、地府判官（质量），并分别展示数量、判词与问题列表。  
**Given** 存在安全问题，**When** 判决完成，**Then** 黑无常只显示安全类 Issue，其他判官同理。

### R5 功德值与判词

系统应根据真实 Issue 计算确定性功德值（100 起，极危 −25、高危 −15、中危 −7、低危 −3，最低 0），并生成不虚构问题的阎王判词。  
**Given** 同一源码重复审判，**Then** 分数、Issue 集合与判词一致。  
**Given** 零命中，**Then** 只显示“当前覆盖规则中暂未发现问题”，不得说代码绝对安全。

### R6 申请还阳与 Diff

当用户选择可修复罪状并申请还阳时，系统应展示只读 Monaco Diff、补丁理由，并要求显式确认，绝不自动覆盖源码。  
**Given** 无受控模板的罪状，**Then** 只显示人工建议，不生成假 Diff。  
**Given** 用户确认采用补丁，**Then** 更新编辑器源码，且支持撤销恢复到采用前内容。

### R7 真实验证

采用补丁后，系统应执行静态语法检查与对应规则复扫，分别显示通过/失败/未验证；单元测试永远显示未执行。  
**Given** 语法与复扫均通过，**Then** 显示“本次修复验证通过”，并注明不代表所有漏洞已修复。  
**Given** 任一检查失败，**Then** 不显示通过，并列出实际失败信息。

### R8 离线与兜底

系统应在无网络、无 AI Key 时完整运行，并清晰标识“离线审判”。  
**Given** 审判引擎异常，**Then** 显示错误边界/错误提示且不执行用户代码。  
**Given** 用户连续点击，**Then** 防重复提交，动画总时长不超过 3 秒。

### R9 隐私边界

系统不得执行用户代码、不得默认上传源码、不得在前端暴露密钥、不得自动提交 PR。  
**Given** 用户未主动启用 AI（P1，本次未实现），**Then** 不发生任何源码外发请求。  
**Given** 构建产物，**Then** 不包含任何 AI API Key。

### R10 可选 AI（P1，本次未实现）

若后续接入 AI，应仅由服务端持有密钥、显式征得用户同意、设置超时与长度限制、用 Zod 校验 JSON、回验 evidence 与行号，并将无法验证内容标为“AI 建议·待核实”，不得污染规则结果或计算功德。  
**本次 Demo 状态：NOT IMPLEMENTED；离线闭环不受影响。**

## 4. 优先级

- **P0（已完成）**：R1–R9 的离线闭环、真实规则、Diff、复扫、撤销、响应式与舞台模式。
- **P1（未实现）**：R10 云端 AI 三司会审、服务端代理。
- **P2（未实现）**：GitHub 公开仓库导入、分享卡片。

## 5. 关键验收

- 真实编辑器可输入 JS/TS。
- 至少 3 条可靠规则给出准确行号与证据（实际 6 条）。
- 三位判官按真实问题展示结果。
- 判词不虚构问题。
- 至少一个内置样例完成 Diff → 确认 → 复扫（实际两个模板）。
- 无网络、无 AI Key 可演示。
- 构建与测试真实执行，结果可复核。
